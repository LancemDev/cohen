# Cohen

**Human music, verified.**

Cohen is a Chrome extension that estimates whether the music playing on YouTube was made by a human or generated by AI — then lets you mute, skip, or allow it based on your own rules.

It combines contextual signals, acoustic measurements, and Gemini models running through Firebase AI Logic. Where possible, classification happens **on your device** with Gemini Nano; ambiguous tracks can be escalated to the cloud for a deeper listen.

> Cohen is an independent project. It is not affiliated with, endorsed by, or sponsored by YouTube or Google.

---

## Why

Generative music tools have made it trivial to publish unlimited tracks. Listeners who want human-made music currently have no reliable way to tell the difference: platforms do not consistently label AI-generated audio, and the ear is not a dependable detector.

Cohen is a personal filter, not a judge. It shows its evidence, exposes its confidence, and always lets you override the result.

## What it does

- Detects the currently playing YouTube track and screens it automatically.
- Combines metadata, channel provenance, acoustic features, and model reasoning into a single verdict: **Human**, **AI**, or **Uncertain**.
- Shows a compact badge on the player with the score and the reasons behind it.
- Can mute or skip tracks classified as AI.
- Deep-scans a track's audio on demand, with a short local clip and an optional cloud escalation.
- Remembers verdicts and lets you mark a channel as trusted or blocked, with channel rules managed in settings.
- Works offline for the on-device path once the model is available.

## How it works

```
YouTube page
   │  metadata (title, channel, description, duration)
   ▼
Content script ──► service worker ──► verdict cache
                        │
                        ├─ contextual heuristics
                        │     keywords, channel provenance, upload patterns
                        │
                        ├─ on-device Gemini Nano (Firebase AI Logic)
                        │     text + acoustic features → structured verdict
                        │     free, private, offline
                        │
                        └─ cloud Gemini (Firebase AI Logic fallback)
                              short audio clip for ambiguous tracks
                              explicit opt-in
```

The model is asked for a conservative, evidence-based verdict with structured JSON output. Cohen fuses that with deterministic signals and never presents a coin flip as certainty.

## Acoustic features

Audio scanning is user-initiated. A short tab-audio clip is analyzed locally for:

- RMS energy and dynamic range
- spectral centroid, flatness, and rolloff
- zero-crossing rate
- silence ratio
- tempo estimate and rhythmic stability
- stereo width

These features are weak evidence on their own. They exist to give the model measurable context, not to claim forensic certainty.

## Privacy

- Automatic screening uses page metadata only.
- Audio is captured only when you explicitly start a deep scan.
- On-device inference sends nothing off the machine.
- Cloud escalation is opt-in. When it is enabled, metadata can fall back to the cloud and deep scans can upload the short WAV clip being analyzed.
- Verdicts and settings are stored in `chrome.storage.local`; nothing is synced by default.

## Status

Early development. The extension is functional as a local prototype; Firebase project credentials and production App Check attestation still need to be configured for cloud features.

## Development

Requirements: Node.js 20+, Chrome 139+ for on-device inference.

```bash
npm install
npm run build
```

Load the unpacked extension:

1. Open `chrome://extensions`.
2. Enable **Developer mode**.
3. Choose **Load unpacked** and select the `dist/` directory.

For on-device inference, enable `chrome://flags/#prompt-api-for-gemini-nano-multimodal-input` and let Chrome download the model.

### Viewing logs

1. Open Cohen options and enable **Debug logging**.
2. Reload the extension and refresh the YouTube tab.
3. Open the relevant DevTools console and filter for `[cohen]`:
   - **YouTube badge/content script**: YouTube tab → DevTools → Console.
   - **Service worker/orchestration**: `chrome://extensions` → Cohen → **Details** → **Inspect views: service worker**.
   - **Popup**: open the popup → right-click it → **Inspect** → Console.
   - **Options page**: open options → DevTools → Console.
   - **Offscreen model/audio work**: if Chrome lists it, use **Inspect views** for the offscreen document; otherwise open `chrome-extension://<extension-id>/offscreen/offscreen.html` in a tab with DevTools.

Automatic classification times out after 30 seconds and deep scans after 120 seconds, so the badge should not stay in a loading state indefinitely.

### Firebase setup

1. Create a Firebase project and enable **AI Logic** with the Gemini Developer API.
2. Register a web app and copy its config into the gitignored `src/config/firebase.local.ts` (copy `src/config/firebase.local.example.ts` if the file is missing).
3. Enforce App Check for AI Logic.
4. For local development, use the App Check debug provider and register the debug token in the Firebase console.

Cloud features stay disabled until a config is present. Cohen degrades to heuristic classification rather than failing closed.

Production App Check from a `chrome-extension://` page needs a supported attestation strategy. The web reCAPTCHA provider loads a remote script that MV3's extension CSP blocks by default, so use a debug token for local development and validate your production provider before shipping.

## Configuration

Settings live in the extension's options page:

- enable or disable screening
- sensitivity thresholds
- automatic mute and skip
- cloud escalation and minimum AI confidence
- cache lifetime
- debug logging
- trusted and blocked channel rules

## Limitations

- AI-music detection is probabilistic. No public, universal provenance signal exists for arbitrary audio.
- Heavily produced human music can look synthetic; well-produced AI music can look human.
- YouTube's DOM changes; selectors may need maintenance.
- On-device inference requires supported hardware and a downloaded model.
- Tab capture requires an explicit extension invocation on the tab (opening the popup or using the badge is the intended flow).
- The extension does not download, fingerprint, or redistribute copyrighted audio.
